# Apollo.RGA личный OlcRTC на A063 — план реализации

**Основание:** [личный тестовый режим](../specs/2026-09-28-apollo-rga-personal-olcrtc-test-mode.md), подтверждённые [Access Bridge](../specs/2026-09-27-apollo-rga-access-bridge-design.md) и [ограниченная сеть](../specs/2026-09-27-apollo-rga-restricted-network-failover-design.md). Исходная подписка и обычные сервера не меняются.

**Принцип исполнения:** сначала отдельные fail-closed контракты и прицельные проверки, затем одно изолированное серверное испытание и A063. Source-only, SOCKS-only и UI-индикатор не считаются физическим доказательством работы OlcRTC. Не подключать подписчиков и не менять production Remnawave.

## 1. Отдельный тестовый журнал

- [ ] Добавить независимые таблицы/методы A063-only сессий: канонический субъект, привязанная установка, session ID, последняя подтверждённая sequence и двусторонний high-water, deadline, состояния `active/closed/unconfirmed`. Никаких ссылок на общий cycle/lease budget и никаких URL/ключей подписки.
- [ ] Проверить идемпотентный повтор, регресс счётчика, conflicting sequence, crash/ambiguous ack, close с неподтверждённым хвостом, гонку disable/close. PostgreSQL-тесты только на отдельной loopback БД; отсутствие такой БД честно отметить.
- [ ] Обычный `policy.Evaluate` и `AlternateAllowed=false` не менять: личный допуск — отдельная явная ветвь, не снимающая production-gate.

## 2. Серверный личный допуск и завершение

- [ ] Привязать A063 через существующий proof-of-possession и точную allowlist установки на сервере; сервер сам проверяет Remnawave `ACTIVE`/expiry и ревизию флага. Клиентский `deviceID`, PSK и debug APK отдельно не дают права.
- [ ] Создать одноразовый room-bound test grant и короткий возобновляемый lease через managed embedding API, а не базовый CLI с default auth. Deadline не позже подписки и пяти минут; при недоступном Bridge дальнейшее продление запрещено. Технический session byte cap достаточно высок для личного теста, не месячный лимит.
- [ ] Подключить durable cumulative reporter к тестовому журналу; при штатном stop, timeout, revoke и crash закрывать session/participant, документировать unconfirmed tail. Проверить чужую установку, replay, просрочку и удалённый active close.
- [ ] Использовать выделенную существующую комнату; не утверждать её provider-side удаление. Не использовать `install.sh` с host networking/restart и выводом ключей без переработки.

## 3. Android: реальный автоматический переход

- [ ] Сохранить обычный хост предпочтительным. Подключить уже созданные classifier/physical-network probe к сервису с ограничением частоты и поколением сети; 2 раунда + отказ выбранного транспорта, не Wi-Fi toggle сам по себе.
- [ ] Получать test grant только для привязанной подписки/установки; при отсутствии доступного carrier не объявлять OlcRTC работающим. Автопереход должен сохранять fail-closed TUN или доказанный Android lockdown, защищать транспортные сокеты от петли и пересоздавать SOCKS/bridge.
- [ ] Независимым UID и пакетным/счётчиковым доказательством подтвердить полный TUN-путь, RU-direct и зарубежный выход; SOCKS-only не даёт `Connected`. Проверить ручное отключение, экран/сон, Wi-Fi→LTE→Wi-Fi, ограниченный LTE и обычный LTE без ложного переключения.
- [ ] В тестовом интерфейсе отдельно и понятно показать режим «Ограниченная сеть», `проверяем/переключаемся/работает/недоступен`, без обещаний UDP, IPv6 и общей квоты, пока они не доказаны.

## 4. Воспроизводимая сборка и A063

- [ ] Материализовать точный pinned OlcRTC fork с проверенным managed patch; сборка AAR/APK из исходников с зафиксированными toolchain/хешами. Проверить отсутствие секретов и сырого grant/room в APK и логах.
- [ ] Установить **отдельный** личный test package на A063, не заменяя подписанный обычный Apollo.RGA; использовать существующую ссылку без нового аккаунта. После проверки не оставлять висящую сессию и временную подписку без явного согласования.
- [ ] Серверно и с телефона подтвердить остановку после disconnect и expiry, запись байтов после disconnect и отсутствие работающего участника в комнате. Если provider не даёт API удаления комнаты, проверить лишь доступный lifecycle и честно указать ограничение.
- [ ] Лишь после принятой личной сборки проектировать собственный подписанный OTA manifest; до него допустима ручная установка/замена через ADB. Никакой публикации обычным пользователям из этого плана.
